## 四、什么是智能体

可以先使用一个工程化定义：

> 智能体是一个能够接收环境信息、围绕目标作出决策、调用工具执行行动，并根据执行结果继续调整行为的系统。

这个定义中有五个重要元素：

- **目标（Goal）**：系统最终要完成什么。
- **环境（Environment）**：智能体所处并与之交互的外部世界。
- **感知（Perception）**：智能体从环境获得信息的过程。
- **决策（Decision）**：根据目标、上下文和当前状态选择下一步行动。
- **行动（Action）**：调用工具或改变外部状态。

一个系统使用了 LLM，不一定就是 Agent。关键在于它是否形成了某种闭环：

```text
获得目标 → 观察当前状态 → 决定下一步 → 执行动作 → 获取结果 → 再次决策
```

### 示例：数据分析智能体

用户提出：

> 请分析这份销售数据，找出最近三个月收入下降的主要原因。

智能体可能执行以下过程：

1. 读取 CSV 的字段和数据类型。
2. 检查缺失值、异常值和日期范围。
3. 制订分析计划。
4. 调用 Pandas 工具按月份、区域和产品聚合。
5. 检查计算结果是否足以支持结论。
6. 如果证据不足，继续分析客户或渠道维度。
7. 生成图表，并给出有数据依据的结论。

这里 LLM 主要负责理解目标、规划和选择工具；真正的数值计算应尽量交给确定性的程序完成。

## 五、LLM、Workflow 与 Agent 的区别

| 类型 | 核心特点 | 控制流程由谁决定 | 适用场景 |
|---|---|---|---|
| 普通 LLM 调用 | 输入文本，生成文本 | 调用程序或用户 | 总结、翻译、分类、问答 |
| Workflow | 步骤提前确定 | 开发者 | 稳定、重复、规则明确的业务流程 |
| Agent | 根据当前状态动态选择下一步 | 模型与程序共同决定 | 路径难以提前穷举的开放任务 |

### 1. 普通 LLM 调用

```text
用户输入 → Prompt → LLM → 文本回答
```

它通常不会主动查询数据库、验证计算结果或根据工具反馈重新规划。

### 2. 固定工作流

```text
读取文件 → 清洗数据 → 生成摘要 → 发送邮件
```

每一步由开发者提前规定。即使某一步使用 LLM，整体仍可能只是工作流。

### 3. Agent

```text
接收目标
  ↓
判断需要哪些信息
  ↓
选择并调用工具
  ↓
观察工具结果
  ↓
继续、修正、换工具或结束
```

Agent 的价值不是“步骤越多越好”，而是允许系统在不确定环境中根据反馈调整路径。

### 判断技巧

可以问三个问题：

1. 下一步行动是否必须根据运行时信息决定？
2. 是否存在多条无法提前完整枚举的解决路径？
3. 系统是否需要根据工具结果调整后续行动？

如果大部分答案是“否”，普通程序或 Workflow 往往更加可靠、便宜和容易测试。

## 六、从 Java 工程视角理解 Agent

可以把最小 Agent 看作一组可组合的组件：

| Agent 概念 | Java 工程中的近似类比 |
|---|---|
| LLM | 一个具有不确定输出的外部决策服务 |
| Tool | Service、Repository 或第三方 API Adapter |
| Prompt | 决策规则、输入契约和运行说明的组合 |
| Message | DTO / Event |
| Memory | 会话状态、缓存或持久化存储 |
| Agent Loop | 状态机或带反馈的编排循环 |
| Guardrail | 参数校验、权限控制和业务规则 |
| Evaluator | 自动化测试、质量检查与运行指标 |

一个概念性的 Java 接口可能是：

```java
public interface Tool {
    String name();
    ToolResult execute(ToolInput input);
}

public interface Agent {
    AgentResult run(Goal goal, AgentContext context);
}
```

不过要注意：LLM 的输出不像普通 Java 方法那样完全确定。因此，Agent 工程尤其需要：

- 结构化输入输出；
- 超时、重试与失败降级；
- 权限和工具调用边界；
- 完整日志和执行轨迹；
- 测试集与效果评估；
- 成本、延迟和 Token 监控。

## 七、Agent 的自主性不是越高越好

Agent 经常被描述为“自主系统”，但工程实践中自主程度应受到控制。

可以把系统分成三个层次：

1. **建议型**：Agent 给出建议，由人决定是否执行。
2. **受控执行型**：Agent 可以调用白名单工具，重要操作需要确认。
3. **自主执行型**：Agent 能够持续规划并改变外部状态。

对于删除数据、发送邮件、支付、发布内容等高影响操作，应保留审批、权限和审计机制。一个可靠的 Agent，不是完全没有约束，而是在明确边界内具有适当自主性。

场景：用户上传一份电商订单 CSV，并提出：

> 找出利润率最低的三个产品类别，分析可能原因并生成图表。

请填写：

| 元素 | 你的答案 |
|---|---|
| 目标 |  |
| 环境 |  |
| 感知到的信息 |  |
| 可以使用的工具 |  |
| 需要作出的决策 |  |
| 执行的行动 |  |
| 完成条件 |  |
| 主要风险 |  |

参考思路：

- 不能直接让 LLM 心算利润率，应调用 Pandas 或 SQL。
- 必须确认利润率的业务定义，例如 `(收入 - 成本) / 收入`。

- 图表应来源于实际计算结果，而不是模型虚构的数据。

## 十、自测题

1. 使用 LLM 的系统一定是 Agent 吗？
2. Agent 的行动只能是生成文字吗？
3. 为什么确定性的数值计算更适合交给 Pandas 或 SQL？
4. Workflow 和 Agent 的核心区别是什么？
5. 为什么 Agent 需要观察工具执行结果？
6. 为什么高自主性可能带来工程风险？

### 参考答案

1. 不一定。只有一次文本生成的程序通常只是 LLM 应用。
2. 不是。行动还可以是查询数据库、调用 API、运行分析工具或修改外部状态。
3. LLM 生成具有概率性，确定性工具更准确、可复现、可测试。
4. Workflow 的路径主要由开发者预先确定；Agent 会根据运行时状态动态选择行动。
5. 工具结果可能成功、失败或暴露新信息，后续决策必须据此调整。
6. 错误决策可能被真正执行，因此需要权限、审批、审计和安全边界。
