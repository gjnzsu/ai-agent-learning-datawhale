# 第六周：KYC/信贷材料初审辅助 Agent 综合 PoC 学习计划

> 将 Agent 课程与 `ai-python-learning-pathway` 合并为一个毕业项目

## 一、本周目标

使用公开制度、合成材料规则和合成客户 Case，完成一个能够检索审查依据、检查材料完整性与一致性、生成带引用审查摘要，并把最终决定交给 Auditor 的辅助 Agent 原型。

本周不重复学习 Python 语法、Pandas、pytest、HTTPX、Pydantic 和 Agent 基础概念，而是把已经掌握的能力串成一个可运行、可评估、可演示的应用。

## 二、项目定位

### 目标用户

KYC Auditor、信贷材料初审人员和 PoC 评审者。

### 核心问题

Auditor 需要在多个材料和制度要求之间反复核对，容易遗漏缺失材料、字段冲突、版本变化和例外条款。Agent 负责整理证据与生成审查草稿，但不作出正式审批决定。

### PoC 能力

```text
公开制度/合成材料规则 + 合成客户 Case
→ 文档解析与结构化切块
→ Embedding 与本地向量检索
→ 权限和有效期过滤
→ 调用只读材料完整性/一致性工具
→ LLM 生成带引用的 KYC/信贷初审摘要与建议
→ 证据不足、冲突或高风险时转 Auditor
```

### 非目标

- 不接入真实客户数据；
- 不连接生产银行系统；
- 不执行正式审批、客户风险定级、转账或客户通知；
- 不自动修改正式业务状态；
- 不让 LLM 替代确定性规则校验或人工责任；
- 不将 PoC 描述为生产就绪系统。

## 四、建议时间安排

### 第 1 天：范围与数据

- 确定公开制度/合成规则的来源和使用许可；
- 明确 Auditor、Case 范围、人工审批点与停止边界；
- 定义知识文档、合成客户材料与 Case 输入契约；
- 设计 5～10 个代表性 Case。

### 第 2 天：解析与检索

- 解析文档并保留标题、版本和来源；
- 比较固定长度切块与结构化切块；
- 建立本地向量索引；
- 验证 Top-k 检索结果。

### 第 3 天：审查草稿与引用

- 组装制度证据与 Case 事实上下文；
- 生成结构化审查摘要和建议；
- 验证引用支持材料要求，Case 字段支持事实陈述；
- 实现证据不足、材料冲突和高风险时转人工。

### 第 4 天：工具与服务化

- 增加材料完整性或字段一致性检查工具；
- 使用 FastAPI 暴露 Case 审查接口；
- 增加输入、错误和权限契约；
- 测试超时、工具失败和越权路径。

### 第 5 天：评估与安全

- 建立 10～30 条最小评估集；
- 分别评估检索和生成；
- 加入缺失材料、证据不足、冲突和 Prompt Injection 用例；
- 运行版本回归并形成 Scorecard。

### 第 6 天：可观测性与 Docker

- 记录请求、Release、模型、Prompt、文档和工具版本；
- 记录延迟、Token、成本和错误类别；
- 增加健康检查；
- 使用 Docker 打包并从干净环境运行。

### 第 7 天：演示与复盘

- 完成 README、架构说明和演示脚本；
- 演示正常初审、缺失材料、证据冲突、工具失败和越权拦截；
- 执行 Go/No-Go 评审；
- 记录 PoC 到生产的差距和下一步路线图。

## 五、与 Python 路线的复用

| 已掌握能力 | 本周如何复用 |
|---|---|
| Pydantic | 定义 Case、审查结果、引用和错误结构 |
| HTTPX | 调用模型或依赖服务 |
| pytest | 执行检索、权限、工具和 API 回归测试 |
| 类型标注 | 明确组件输入输出契约 |
| 异常与重试 | 处理模型、检索和工具失败 |
| Prompt 对比 | 比较审查草稿与转人工策略版本 |
| 数据契约 | 验证文档来源、版本和元数据 |
| 数据泄漏意识 | 隔离测试答案、未来文档和无权限资料 |
